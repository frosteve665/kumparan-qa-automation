# BUG-003: React hydration mismatch (error #418) on the desktop homepage

| Field | Value |
|---|---|
| Severity / Priority | Medium / P2: the server-rendered page is discarded and re-rendered on the client, delaying interactivity |
| Environment | Production, desktop kumparan.com (Chrome): homepage on every load, and also seen on the report page (`/report/story/...`) loaded directly. Not observed on m.kumparan.com. 2026-10-09, re-checked 2026-10-12 |
| Account | Guest |
| Reproduction rate | 100% on desktop: 3/3 in Google Chrome without ad blocking, also with an Asia/Jakarta timezone (re-verified 2026-10-11). Mobile 0/3 |
| Automated check | TC-NAV-005 (`tests/web/navigation/TC-NAV-005_No_JavaScript_Errors.spec.ts`; known defect on desktop: `test.fail`) |

## Steps to reproduce
1. Open `https://kumparan.com` with the browser console open.

## Expected result
No uncaught errors from the page's own scripts.

## Actual result
An uncaught error is thrown on every load:

```
Minified React error #418; visit https://react.dev/errors/418?args[]=HTML&args[]= ...
```

React error 418 means the HTML rendered on the server does not match what the client renders
during hydration (https://react.dev/errors/418), so React discards the server markup and renders
the tree again on the client. The error is identical with third-party ads blocked, so it comes
from kumparan's own code, not from an ad script.

## Impact observed during testing
Interactivity arrives late after the content is visible. The automation saw the consequences:
- An early Enter in the header search box submits the plain HTML form and lands on
  `/?desktop-search=<term>` with no results (OBS-002).
- Early clicks on report reasons tick the native checkbox without the app registering it, so
  "Laporkan" stays disabled.
The suite works around this with `waitForInteractive` (it waits for React's event handlers), but
real users on slow devices experience it directly.

## Evidence
- Video of the run that captured the error: [evidence/BUG-003-desktop.webm](evidence/BUG-003-desktop.webm)
- Assertion message in the evidence dashboard (TC-NAV-005, desktop-chrome)

## Suggested fix
Find the mismatching component with a development build (React reports the exact node), and
typical causes: time/locale formatting ("2 jam" vs server time), `typeof window` branches,
random IDs.
