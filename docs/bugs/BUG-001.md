# BUG-001: "Batal" on a directly opened report link leaves kumparan for a blank page

| Field | Value |
|---|---|
| Severity / Priority | Medium / P2: a reader who opens a shared or bookmarked report link and cancels is dropped out of the site |
| Environment | Production. Desktop Chrome 1440x900 (kumparan.com) and Pixel 7 emulation (m.kumparan.com), Playwright 1.64, 2026-10-09 |
| Account | Guest (also expected for signed-in users: the cause is navigation history, not auth) |
| Reproduction rate | 100% (every automated run on both platforms; manual check confirmed) |
| Automated check | TC-RPT-009 in `tests/web/engagement/report.spec.ts` (known defect: `test.fail`, reported as DEFECT) |

## Preconditions
The report form is opened **directly** (new tab, shared link, bookmark), so there is no previous
page in the tab's history.

## Steps to reproduce
1. Open a new tab at `https://kumparan.com/report/story/<story-slug>` (any live story).
2. Click **Batal**.

## Expected result
The reader stays on kumparan: back to the reported story (or the homepage if the story is unknown).

## Actual result
The tab navigates to `about:blank`: an empty page outside the site with no way back except the
browser's own controls. "Batal" calls `history.back()` unconditionally; with no history entry,
the browser falls back to a blank page.

Opening the form from a story and pressing "Batal" works (TC-RPT-004), so only entry by direct link is affected.

- Video, desktop: [evidence/BUG-001-desktop.webm](evidence/BUG-001-desktop.webm)

## Scope and suggested fix
Desktop and mobile, any story. Fall back to the story URL (which the form already knows from its
own path) when `history.length <= 1` or the referrer is not kumparan.
