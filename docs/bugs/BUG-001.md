# BUG-001: "Batal" on the report form only goes back in browser history: a dead button on shared links

| Field | Value |
|---|---|
| Severity / Priority | Medium / P2: a reader who opens a shared report link cannot cancel; a reader coming from another site is sent away from kumparan |
| Environment | Production. Google Chrome (desktop 1366x800) and Pixel 7 emulation, no ad blocking, no test fixtures. Re-verified 2026-10-11 |
| Account | Guest (the cause is navigation history, not authentication) |
| Reproduction rate | 100% for each entry path below, desktop and mobile |
| Automated check | TC-RPT-009 in `tests/web/engagement/report.spec.ts` (real-user path; known defect: `test.fail`) |
| Verification script | `npx tsx scripts/repro/verify-bugs.ts` (results in `evidence/verification/results.json`) |

## What "Batal" does, by how the reader reached the form

| Entry path | History length | Result of "Batal" | Verdict |
|---|---|---|---|
| Report link opened **in a new tab** (shared or "open in new tab") | 1 | **Nothing happens: the form stays on screen** | Defect |
| Arrived from **another website** (e.g. a link in a web chat) | 3 | **Leaves kumparan** for the previous website | Defect |
| Opened from the story ("Laporkan tulisan") | 3 | Returns to the story | Correct |

Conclusion: "Batal" calls `history.back()` unconditionally instead of returning to the story it
belongs to.

> **Correction (2026-10-11).** The first version of this report said "Batal leads to `about:blank`".
> That came from automation: a Playwright tab starts at `about:blank`, so going back lands there.
> Re-testing the real entry paths in Google Chrome showed the actual user impact is the dead button
> and the exit from the site described above. The automated test now uses the real path.

## Steps to reproduce (most common path)
1. On kumparan.com (or m.kumparan.com), open a story's report link in a **new tab**:
   `https://kumparan.com/report/story/<story-slug>`.
2. Click **Batal**.

## Expected result
The reader leaves the form and returns to the reported story (the form already knows the story from
its own URL).

## Actual result
Nothing happens. The form stays on screen; the only way out is the browser's own controls.

## Evidence
- Real-Chrome verification, all entry paths: [evidence/verification/results.json](evidence/verification/results.json)
- Screenshots after "Batal": `evidence/verification/BUG-001-desktop-link-in-new-tab.png`, `BUG-001-mobile-link-in-new-tab.png`, `BUG-001-*-from-other-site.png`

## Suggested fix
Navigate to the story URL instead of `history.back()` when there is no same-site history entry
(`history.length <= 1` or `document.referrer` not on kumparan).
