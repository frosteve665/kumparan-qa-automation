# BUG-002: Address bar switches back to the story while the report form is on screen

| Field | Value |
|---|---|
| Severity / Priority | Low / P3: refresh, bookmark or share of the page leads to the story, not to the form the reader sees |
| Environment | Production. Desktop Chrome (kumparan.com) and Pixel 7 emulation (m.kumparan.com), 2026-10-09 |
| Account | Guest |
| Reproduction rate | **Intermittent.** Desktop 2/6, mobile 3/7 across automated attempts (see timeline file) |
| Automated check | TC-RPT-012 in `tests/web/engagement/report.spec.ts`, kept as an executable reproduction under `test.fixme` (an intermittent defect is not a reliable gate). Reproduction script: `npx tsx scripts/repro/bug-002.ts 5` |

## Preconditions
The reader has scrolled to the end of a story (the end-of-article tracker has fired and switched
the URL to `/<channel>/<slug>/full`).

## Steps to reproduce
1. Open a story and scroll to the end.
2. Click **Laporkan tulisan**.
3. Watch the address bar for a few seconds while the report form is shown.

## Expected result
The address bar stays on `/report/story/<slug>` while the report form is displayed.

## Actual result
The form is displayed, but the URL is rewritten back to the story URL. In one recorded desktop
attempt it was rewritten **9 times within 4 seconds** after reaching `/report/story/<slug>`:

```
/kumparannews/<slug>
/report/story/<slug>
/kumparannews/<slug>   (x9, while the report form stays on screen)
```

This points to the article's scroll/URL tracker (the listener that switches to `/full`) still
running after the reader has navigated to the report route: a listener that is not cleaned up
when the article unmounts.

## Evidence
- Screenshot with the address bar URL stamped on the page: [evidence/BUG-002-desktop.png](evidence/BUG-002-desktop.png)
- URL timelines of every attempt: [evidence/BUG-002-timeline.json](evidence/BUG-002-timeline.json)

## Scope and suggested fix
Desktop and mobile. Remove the article's scroll/history listeners on unmount (or guard them with
the current route) so they cannot rewrite the URL of another page.
