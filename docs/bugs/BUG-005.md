# BUG-005 (API): Negative page limit is accepted and returns almost the whole collection

| Field | Value |
|---|---|
| Severity / Priority | Medium / P2: an out-of-range limit becomes an unbounded query (performance and data-exposure risk) |
| Environment | GraphQLZero, https://graphqlzero.almansi.me/api, 2026-10-09 |
| Reproduction rate | 100% |
| Automated check | TC-API-019 in `tests/api/graphql/negative.spec.ts` (known defect: `test.fail`) |

## Steps to reproduce
POST to the endpoint:

```json
{ "query": "query ListPosts($o: PageQueryOptions) { posts(options: $o) { data { id } meta { totalCount } } }",
  "variables": { "o": { "paginate": { "page": 1, "limit": -5 } } } }
```

## Expected result
`BAD_USER_INPUT` for `limit < 1` (boundary: 0 and negative values are invalid page sizes).

## Actual result
`200`, no errors, and **95 posts**: everything except the last 5. The limit is apparently passed
straight to an array slice (`slice(0, -5)` semantics) without validation.

## Evidence
[evidence/BUG-005-response.json](evidence/BUG-005-response.json):

```json
{ "returnedRows": 95, "firstIds": ["1","2","3","4","5"], "totalCount": 100, "errors": null }
```
