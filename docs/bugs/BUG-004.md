# BUG-004 (API): Unknown post id returns a ghost object instead of null

| Field | Value |
|---|---|
| Severity / Priority | Medium / P2: clients cannot tell "not found" from a real post and may render an empty post |
| Environment | GraphQLZero, https://graphqlzero.almansi.me/api, 2026-10-09 |
| Reproduction rate | 100% |
| Automated check | TC-API-018 in `tests/api/graphql/negative.spec.ts` (known defect: `test.fail`) |

## Steps to reproduce
POST to the endpoint:

```json
{ "query": "query GetPost($id: ID!) { post(id: $id) { id title body user { id } } }", "variables": { "id": "999999" } }
```

## Expected result
`200` with `"data": { "post": null }` (the field is nullable), or a `NOT_FOUND` error.

## Actual result
`200` with an object whose every field is null, including the nested user:

```json
{"data":{"post":{"id":null,"title":null,"body":null,"user":{"id":null}}}}
```

Re-verified 2026-10-11 (schema introspection plus ids `999999`, `101` and `0`, all identical):
the schema declares `post` as nullable `Post` and `id` as nullable `ID`, so the response is
**schema-valid**. The defect is the contract: a nullable field exists precisely to say "not found",
yet the API never uses it, so "no such post" is indistinguishable from a real post and passes
naive `if (data.post)` checks in clients.
