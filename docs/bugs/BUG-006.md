# BUG-006 (accessibility): Share modal is not an accessible dialog: Escape does not close it

| Field | Value |
|---|---|
| Severity / Priority | Medium / P2 for accessibility (keyboard and screen-reader users); Low for others |
| Environment | Production. Desktop Chrome (kumparan.com) and Pixel 7 emulation (m.kumparan.com), 2026-10-10 |
| Found by | Playwright **healer agent** (Task C), then confirmed by hand on both platforms |
| Reproduction rate | 100% |
| Automated check | TC-AGT-009 in `tests/agent/share/share.agent.spec.ts` (known defect: `test.fail`) |

## Steps to reproduce
1. Open any story.
2. In the share bar, click the "more" (⋮) icon: the share modal opens.
3. Press **Escape**.

## Expected result
Following the WAI-ARIA dialog pattern (https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/):
Escape closes the modal; the modal has `role="dialog"` and `aria-modal="true"`; focus moves into it
when it opens and returns to the trigger when it closes.

## Actual result
| Check | Desktop | Mobile |
|---|---|---|
| Escape closes the modal | No | No |
| `role="dialog"` / `aria-modal` | Missing | Missing |
| Focus moved into the modal on open | No | No |
| Backdrop click closes it | Yes | Yes |
| Close button closes it | Yes | Yes |

Keyboard users cannot dismiss the modal without tabbing through the page behind it, and screen
readers do not announce it as a dialog (WCAG 2.1.2 No Keyboard Trap, 2.4.3 Focus Order, 4.1.2
Name, Role, Value).

## Evidence
Automated check output (TC-AGT-009) and the attribute probe above, run on both platforms.
